# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/), and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased (0.6.0)]

### Added
- **Standalone `.cs` file support** — any tool's `solutionPath` now also accepts a single `.cs` file (a .NET 10 "file-based program" you'd launch with `dotnet run file.cs`), with or without `#:` directives (`#:package`, `#:project`, `#:sdk`, `#:property`). The SDK itself turns the file into a project: the server calls `dotnet run-api` (the same mechanism Roslyn's own language server uses) to get the exact virtual project, then loads it through the normal MSBuildWorkspace pipeline. A standalone file therefore behaves like a real project — it gets the SDK's **default analyzers and source generators** (so `[GeneratedRegex]` and friends work even with no directives), `#:package` references resolve, `#:project` references load as **source** projects (go-to-definition / find-references cross into them), and diagnostics match `dotnet build`/`dotnet run`. Editing a file's `#:` directives rebuilds the project; editing only its code updates incrementally. The project is materialized in place — at `<entry>.cs.csproj` in the entry file's directory, exactly where the SDK/LSP put it — so the entire repo MSBuild context (`Directory.Build.props`/`.targets`, `global.json`, `NuGet.config`, `Directory.Packages.props`) is honored by construction, not approximated. That wrapper is git-ignored (best-effort, via the repo's local `.git/info/exclude`, so no tracked `.gitignore` is touched), is deleted immediately once loaded, and is the only thing written into your tree — build output goes to the SDK's own artifacts location, same as `dotnet run`. If the SDK can't produce a project (e.g. `dotnet run-api` unavailable) the server falls back to a framework-only in-memory workspace so the file still loads.
- **Workspace caching** — a loaded solution is now cached (default 20-minute idle TTL) and reused across tool calls instead of paying a full MSBuild load every time. Edits to tracked files are applied incrementally as in-place document text updates; project-file and Razor changes still trigger a reload.
- **Incremental document reconciliation** — newly added, removed, or renamed `.cs` files are picked up by re-evaluating just the affected project with MSBuild and applying the difference, instead of reloading the whole solution. MSBuild — not a path guess — decides which files belong to the project (globs, `<Compile Remove>`, links).
- **Analyzer & source-generator shadow-copy loader** — analyzer/generator assemblies load from a private per-process temp copy (the way Visual Studio does), so a concurrent `dotnet build` is no longer blocked by build output the server holds open (MSB3026/MSB3027/MSB3021). Each analyzer directory gets its own isolated loader, dependencies resolve to the highest matching version, and stale copies are cleaned up during the session. Opt out with `ROSLYNMCP_DISABLE_ANALYZER_SHADOW_COPY=1`.
- **HTTP transport mode** — the server can run over HTTP in addition to stdio.
- **Razor / Blazor diagnostics** — `get_diagnostics` now accepts `.razor` and `.cshtml` files and reports RZ diagnostics against the source file (not the generated `.g.cs`). When the Razor generator can't be loaded it reports an `RMCP0001` info diagnostic, and a generator that throws at runtime reports `RMCP0002`, so an unexpectedly empty result is explained instead of silent.
- **Symbol-search candidates on build errors** — symbol search responds with possible matching candidates when the project has build errors instead of failing outright.
- **Wrong-column recovery** — when a supplied `line`/`column` lands on the wrong identifier (e.g. `TimeSpan` instead of `FromSeconds` in `TimeSpan.FromSeconds`) but a `symbolName` was given, the tool scans the line for a unique match, retries there, and reports the corrected location.
- **Claude Code plugin definition** plus a `/setup` slash command that guides installation of the `roslyn-mcp` .NET global tool after the plugin is cloned.
- Local install scripts [install-local.ps1](./install-local.ps1) for the `roslyn-mcp` dev tool and `roslyn-cli`.
- **`get_diagnostics` scoping and filters** — `projectPath` compiles and reports only one project of the solution (all of its target frameworks), so the call no longer pays for the whole solution; `diagnosticIds` / `excludeDiagnosticIds` keep or drop IDs (case-insensitive, the exclusion wins); `messageFilter` keeps diagnostics whose message contains a case-insensitive substring; `maxResults` caps the list, with `totalCount` counting every match and a new `truncated` flag. The filters cover the synthetic `RMCP0001`/`RMCP0002` entries and generator-reported (e.g. `RZ`) diagnostics as well, `projectPath` keeps only the `RMCP0001` load issues of its own project, and everything combines with `sourceFile` and `severityFilter`.
- **`search_symbols` matching and scoping** — `exactMatch` matches the whole symbol name instead of a substring, and `caseSensitive` matches the query case-sensitively (both default to `false`, which keeps the case-insensitive substring match). `projectPath` searches and compiles only one project of the solution (all of its target frameworks); `namespaceFilter` keeps symbols declared in a namespace or one nested in it, by whole segments and case-insensitively (`App.Core` matches `App.Core.X` but not `App.CoreUtils`); `sourceFile` keeps symbols declared in one file, a partial type when any of its declarations is there, and reports that declaration's location. `totalCount` now counts a symbol compiled for several target frameworks once, also past `maxResults`.
- **`find_references` scoping** — `includeDeclaration: false` returns usages only (the default `true` keeps the declarations); `referenceFile` keeps references located in one file and `projectPath` those in one project of the solution (all of its target frameworks). Both also narrow the documents Roslyn searches, so a scoped call on a widely used symbol does less work. The filters run before `maxResults`, so `totalCount` and `truncated` describe the filtered set.
- **`find_callers` scoping** — `callerFile` keeps the call sites located in one file and `projectPath` those in one project of the solution (all of its target frameworks), applied before `maxResults` and narrowing the documents searched, like `find_references`' `referenceFile` / `projectPath`.
- **Direct descendants only** — `find_implementations` and `get_type_hierarchy` take `transitive` (default `true`); `false` leaves out what is reached only indirectly. For a class that is Roslyn's non-transitive derived-class search; for an interface, the types (and, in `get_type_hierarchy`, interfaces) that list it in their own base list, so a subclass of an implementer or a type implementing it through a derived interface is left out; for an interface member, the implementations of those direct implementers, an inherited one included. `get_type_hierarchy` also takes `maxResults` for its derived types and reports `derivedTypesTotalCount` and `derivedTypesTruncated`.
- **`get_document_outline` depth, filters and cap** — `maxDepth` limits how deep the outline goes, with namespaces not counting (`1` = top-level types only, `2` = plus their members); `kindFilter` (the `search_symbols` kind names, a constructor counting as `Method` and an enum member as `Constant`) and `nameFilter` (case-insensitive substring) keep the matching entries together with the namespaces and types containing them, so the tree stays navigable; `maxResults` caps the entries, counted depth-first with parents before children, and the result gains a `truncated` flag next to `totalCount`, which counts the filtered outline.
- **`get_symbol_info` member filters** — for a type, `kindFilter` (the `search_symbols` kind names), `nameFilter` (case-insensitive substring) and `accessibilityFilter` (exact declared accessibility: `public`, `internal`, `protected`, `private`, `protected internal`, `private protected`) narrow the listed members, and `maxResults` caps them; the result reports `membersTotalCount` and `membersTruncated`. For any other symbol the options are ignored.
- **`--version` / `-v`** for `roslyn-mcp` and `roslyn-cli`: prints the version (`0.6.0`; a build installed by `install-local.ps1` prints `0.6.0-local`) and exits with 0 before anything else starts, so the server writes no log entry, registers no MSBuild and puts nothing else on stdout. It is the assembly's informational version without the `+<commit>` build metadata, the same string the MCP `initialize` response now reports as `serverInfo.version` (which used the assembly version and so never showed a `-local` suffix). `roslyn-cli` takes the flag as its first argument only, since later arguments can be option values.
- **`change_return_type`** (new tool; 42 tools in total): changes the return type of a method, or the type of a property or indexer (`memberName` `this`), on the same override / implementation family as `change_signature`, with the same refusals. Only the declarations change; return statements, bodies and callers are not rewritten. Instead the result lists under the new `warnings` field the compiler errors the change introduces in the affected documents (the declaring files, the files declaring the members' types, and every file that references a member), each as `path(line,column): error CSxxxx: message`; errors that were there before are not listed. `void` is allowed in both directions for methods (the missing or superfluous `return`s show up among the warnings) and refused for properties and indexers; a `ref` return stays one. `newType` is resolved where the member is declared and written in each member's context like `change_signature`'s types: simplified to what the file's usings allow, `?` on reference types only where nullable annotations are enabled, `T` translated through generic base types. Files keep their encoding and line endings. `preview` returns each declaration's type before and after, plus the warnings. `RefactoringResult` gains the optional `warnings` (omitted when empty), which the CLI's text output lists.
- **`find_unused_symbols`** (new tool; 43 tools in total): lists the types and members declared in source that nothing references outside their own declaration, so a recursive call, a type naming itself or a symbol's own documentation comment is no use, while a `nameof`, a `cref` elsewhere and a reference from source-generated code are. A type counts as used when it or one of its members or nested types is referenced from outside the type (a static class whose extension methods are called is used). By default only symbols not visible outside their assembly are reported, judged by effective accessibility (a public member of an internal type is internal); `includePublic` adds public ones and protected ones in types that can be derived from. Left out because something other than a reference uses them: overrides, interface implementations (implicit, explicit, or for a derived class), the entry point and its types, operators and conversions, finalizers, static and parameterless constructors, primary constructors and positional record properties, partial methods and properties, `extern` members, enum members, and declarations in generated files (`obj/`, `*.g.cs`, `<auto-generated>` headers). Symbols with attributes, types containing them, and fields of `[StructLayout]`, `[InlineArray]` or `[Serializable]` types are left out unless `includeAttributed` is set; attributes that only inform the compiler or debugger (`System.Diagnostics.CodeAnalysis`, `[Obsolete]`, `[MethodImpl]`, `[Debugger*]`) don't count. `projectPath` and `sourceFile` choose where the reported symbols are declared, `kindFilter` their kind, `maxResults` (default 100) caps the list after ordering by file, line and column, with `totalCount` and `truncated`; `symbolsChecked` says how many symbols were searched. A private symbol is searched only in the declarations of the type it is private to, a file-local one in its file, an internal one in its project and the projects its `InternalsVisibleTo` names, in parallel; a symbol of a multi-targeted project is reported only when unused in every target framework. Each entry has name, fully qualified name, kind, containing type, declared accessibility, file, line and column. The results are candidates: reflection, serialization, XAML/Razor bindings, string-based lookups and other assemblies are invisible. On this repository (`RoslynMcp.sln`, 1531 symbols checked) it takes about 2 s after a cold 4 s load and about 0.15 s warm.

### Changed
- **Tool result JSON is now human-readable** — results are tab-indented instead of minified, and non-ASCII / HTML-sensitive characters (umlauts, `<`, `>`, `&`) are emitted verbatim instead of `\uXXXX` escapes. All 41 tool handlers share one `ToolJsonOptions.Default` instance instead of each constructing identical serializer options; the CLI's JSON output uses the same encoder and tab indentation.
- Upgraded to **.NET 11** (`net11.0`, `global.json` pins SDK 11.0.100 with `latestFeature` roll-forward) and **xUnit v3** (4.x). Running the server now requires the .NET 11 runtime. Dependencies: Roslyn 5.12.0, Microsoft.Build.Framework 18.12.2 (plus `Microsoft.NET.StringTools` 18.12.2, which it now depends on, excluded from runtime output like Framework itself so MSBuildLocator's MSBL001 check passes), Microsoft.NET.Test.Sdk 18.12.0, xunit.runner.visualstudio 4.0.1, coverlet.collector 10.1.1.
- Tests run on **Microsoft.Testing.Platform**: xUnit 4 builds MTP test apps, which the .NET 10+ SDK refuses to run through the VSTest-based `dotnet test`, so `global.json` opts the repo into the MTP `dotnet test` experience. CI uses `dotnet test --solution RoslynMcp.sln` and writes TRX via `--report-xunit-trx`; the workflows now set up .NET 11 (they still installed 9.0).
- Workspace load now tolerates per-project failures the way the VS IDE does — NuGet restore problems (e.g. NU1903/NU1904 advisories escalated to errors) no longer abort the whole load; it fails only when no project loads at all.
- External file changes detected by the watcher now wait for any in-flight tool call to finish before updating the solution, so a background edit can't change the code mid-operation.
- Default idle cache TTL raised from 5 to 20 minutes to cover typical "step away" gaps without a cold reload.
- The package version is centralized in `src/Directory.Build.props` (now `0.6.0`); `install-local.ps1` reads that prefix and appends a `-local` suffix, so dev builds (`0.6.0-local`) stay distinguishable from released packages.
- A project is now fully compiled at load time so the reported `workspaceLoadMs` reflects the real cold-load cost rather than deferring it to the first query.
- **`change_signature` changes the whole override / implementation family.** Changing one member of a family alone never compiles, so the change now also applies to what the method overrides (up to the base-most definition), its overrides (transitively, in every project of the solution), the interface members it implements implicitly or explicitly and their other implementations, and to the calls of all of them, `base.M(...)` included. Parameters correspond by position, since an override may name them differently: a rename in the request renames the parameter at that position in every member, with its uses in the bodies and documentation comments and the named arguments of the calls; without a rename each member keeps its own name. A type the request writes is resolved where the method is declared and written in each member's own context (`IEnumerable<T>` in `Repository<T>` becomes `IEnumerable<User>` in `UserRepository : Repository<User>`; `string?` is written `string` in a nullable-disabled file); a type that uses a type parameter with no counterpart in some member is refused (`TypeNotExpressible`, 3111). Explicit interface implementations get no default values (CS1066). When a member of the family is declared only in metadata (an override of `object.ToString`, an implementation of `IDisposable.Dispose`) or in generated code, the tool refuses and names it (`FamilyMemberNotInSource`, 3110), since that member cannot change. There is no option to change one member alone. What `parameters` means (a list of changes or the full new list) is unchanged. `line` may be any line from the declaration's first attribute or modifier to its name. Like `change_return_type`, the result lists under `warnings` the compiler errors the change leaves in the affected documents (the declaring files, the files declaring the members' types, and every file that references a member), such as a method group converted to a delegate it no longer matches or a removed parameter the body still uses, and each `default /* TODO */` placeholder passed for a parameter without a default value (`path(line,column): TODO: ...`).

### Removed
- `rename_symbol` no longer advertises `renameImplementations`. It was never read: Roslyn's renamer always renames interface implementations and overrides together with the member, so `false` had no effect. The parameter is gone from the tool schema, the contract and the CLI (`--rename-implementations`), and the tool description now says that implementations and overrides are always renamed.

### Fixed
- `change_signature` keeps each call's argument order, so the arguments are evaluated as before. Calls were rewritten into the new declaration order: adding a parameter turned `M(b: Next(), a: Next())` into `M(a: Next(), b: Next(), 0)`, which evaluates the two `Next()` the other way round. Now an argument of a removed parameter is dropped in place and a named argument is renamed in place; only positional arguments move when parameters are reordered; a new argument after a named one is passed by name (`M(b: 2, a: 1, c: 0)`); and from the first argument that would be out of position on, the arguments are named instead of moved (CS8323). An optional parameter a call leaves out stays left out; its default value used to be written into the call.
- `change_signature` no longer breaks the code it edits. A kept parameter was rebuilt from its type's display string, so `ref`/`out`/`in`/`params`/`this` and attributes were dropped and the type came out fully qualified (`System.Collections.Generic.List<int>`); it now keeps its own declaration apart from what the request changes. A renamed parameter kept its old name in the method body. Call sites were located by their original positions in documents that had already been edited, so a call after the changed declaration, or a second call in the same file, could hit the wrong node; all edits are now computed against the original syntax and applied in one pass. A method passed as a method group (`Run(Process)`) had the arguments of the enclosing call rewritten; only invocations of the method are rewritten now. Recursive calls were skipped, calls in extension form (`text.Join(a)`) mapped their arguments one parameter off, extra arguments of a `params` parameter were dropped, and only one part of a partial method changed.
- The CLI accepts a relative solution path, as its own usage examples (`roslyn-cli MySolution.sln ...`) show; it is resolved against the current directory. It used to be rejected with "Path must be a .sln, .slnx, .csproj, or standalone .cs file" even when it was one. The server, which needs an absolute path, now says that: "Path must be absolute: ...".
- `get_diagnostics` says what it reports: compiler (CS), source-generator and Razor (RZ) diagnostics plus the RMCP workspace notes. IDE/CA analyzers are not run, so a `diagnosticIds` entry such as `IDE0005` never matches; the description of the tool and of `diagnosticIds` now say so. `search_symbols`' `kindFilter` description lists `Namespace`, which it always accepted.
- `get_diagnostics` reports a diagnostic of a multi-targeted project once. Each target framework is loaded as its own project and compiled on its own, so a warning in shared code was listed, and counted in `totalCount`, once per framework. An identical diagnostic (same ID, location, message and severity) is now listed once, and for a multi-targeted project it names the frameworks that reported it in a new `targetFrameworks` field (left out of the JSON otherwise), so a diagnostic that only one framework's `#if` branch produces is still recognizable. `projectPath`, the filters and `maxResults` work on the deduplicated list.
- `find_implementations` finds the derived classes of a class and the overrides of a virtual, abstract or override member, as its description promised. It relied on Roslyn's `FindImplementationsAsync`, which only knows interfaces and their members, so for an abstract class or an abstract method it returned nothing. `transitive: false` keeps the direct subclasses and the overrides of the member itself (not overrides of those overrides); generic base classes and other projects are covered. Interfaces and interface members work as before.
- `find_references`, `find_callers`, `find_implementations`, `get_type_hierarchy` (derived types) and `get_diagnostics` return their results in a fixed order, so `maxResults` keeps the same first N on every call. Roslyn's `SymbolFinder` searches documents in parallel and compilations bind method bodies concurrently, so the order changed from one call to the next and a truncated list was a different subset each time. Results are now sorted by file, line and column (then name); `find_references` lists the declarations first, then the usages, and a position reported both as a declaration and as a usage is always the declaration; `get_diagnostics` lists the diagnostics without a file (such as `RMCP0001`/`RMCP0002`) first. `search_symbols`, `get_document_outline` and `get_symbol_info` already followed declaration order and are unchanged.
- A `sourceFile` that differs from the loaded path only in letter case works on Windows. The workspace's document lookup normalized both paths but compared them case-sensitively, so `c:\src\app\widget.cs` for `C:\src\App\Widget.cs` failed with "File not found in workspace" in every tool that takes a `sourceFile`. It now compares the way `PathResolver.PathsEqual` does (case-insensitive on Windows, case-sensitive elsewhere), as do the other comparisons of normalized document and project paths in the workspace (incremental reconciliation, the workspace cache keys) and in `get_diagnostics`.
- A file that a refactoring writes under a new name or splits off an existing file keeps that file's encoding. `rename_symbol` with `renameFile` and `move_type_to_file` wrote the result as a brand-new file, which is created as UTF-8 with BOM, so renaming the type in a BOM-less file (the `dotnet new` default) or moving a type out of one produced a file with a BOM. The commit now writes a document moved to a new path in the encoding of its old file, and `move_type_to_file`'s new file in the encoding of the file the type came from (read before anything is deleted, so this also holds when the source file is removed in the same step). `move_type_to_file` also joins the new file's usings, namespace and type with the source file's line ending instead of a hard-coded LF. Files generated from scratch (e.g. `extract_interface` with a new `targetFile`) are still written as UTF-8 with BOM.
- The CLI accepts list parameters. Every option value became a JSON string, number or boolean, so `--members`, `--fields` or `--parameters` could not be given at all, and `extract-base-class` and `change-signature`, which require one, were unusable. A value that is a JSON array or object (`--members '["Print","Other"]'`) is now passed as JSON, and the tool help marks such parameters as `string[] (JSON array)`.
- `implement_interface` (`members`), `generate_equals_hashcode` and `generate_tostring` (`fields`) reject names that match nothing with `MemberNotFound`, like `generate_constructor`, `generate_overrides` and `extract_interface` already did. Unknown names were dropped silently, so a typo generated less than asked for and still reported success. For `implement_interface` only names the interface does not have are rejected; naming a member that is already implemented stays allowed. The `generate_constructor` `members` description no longer claims that only uninitialized fields are used by default: all instance fields are, including ones with an initializer.
- `extract_base_class` no longer loses overloads. `members` selects by name, and the derived class lost every member with a selected name, but only the first overload of a method was moved into the base class; the others were deleted. All members with a selected name now move.
- `rename_symbol` with `renameFile` renames the type's own file even when the rename starts from a usage in another file. The file-name check looked at the file the symbol was found in, so renaming `Widget` from `User.cs` renamed the class but left it in `Widget.cs`. It now uses the declaration whose file is named after the type (for a partial type, the part in that file).
- `get_type_hierarchy` with `direction` `Descendants` (or `Both`) finds the descendants of an interface. Descendants came from `FindDerivedClassesAsync` alone, which finds nothing for an interface, so the list was always empty; for an interface they are now the interfaces extending it and the types implementing it (directly or indirectly).
- `diagnose` reports what it claims to. `msBuildVersion` held the SDK version (`11.0.100`) and `dotnetSdkVersion` the runtime version (`11.0.0`); they now hold the version of the MSBuild that loads projects (its `Microsoft.Build.dll`, e.g. `18.12.2`) and of the .NET SDK it belongs to, and the new `dotnetRuntimeVersion` holds the runtime's. `roslynVersion` is the package version (`5.12.0-…`) instead of the assembly version. `capabilities` lists the tools actually registered (all 41 in the server, the CLI's own names in the CLI) instead of three hard-coded names; without MSBuild only `diagnose` remains. `msBuildFound` no longer says false when MSBuildLocator finds no instance but the SDK-directory fallback would load one: `diagnose` and the workspace load now share one MSBuild selection. Workspace load failures and analyzers/generators that failed to load are reported under `warnings`, each once (a cached workspace collects its load diagnostics again whenever it re-evaluates a project). `verbose`, which was advertised but ignored, now adds `details`: every MSBuild instance found (with its MSBuild version and the selected one marked), why it was selected, the registered MSBuild path, the probed dotnet roots, and with a `solutionPath` each project's target framework, document count, analyzer/generator references (with their analyzer and generator counts) and load failures, plus the workspace load diagnostics. Without `verbose` the output stays as compact as before. The SDK fallback now also probes `DOTNET_ROOT`, the root of the running runtime, the `dotnet` host on `PATH` (following symlinks) and the usual Unix locations (`/usr/share/dotnet`, `/usr/lib/dotnet`, `/usr/local/share/dotnet`, `~/.dotnet`) besides `%ProgramFiles%\dotnet`, and orders a release above a prerelease of the same version (prerelease labels were ignored). The server and the CLI share one implementation; the CLI now also runs `roslyn-cli diagnose [--solution-path <path>] [--verbose]` without a positional solution, as its help already promised.
- `move_type_to_namespace` honors `updateFileLocation`. It was advertised, but the operation never read it and reported success without moving anything. With `updateFileLocation: true` the file now moves into the folder that matches the new namespace below the project's root namespace (`RootNamespace` `App`, namespace `App.Services.Auth` → `<projectDir>/Services/Auth/<File>.cs`), but only when that cannot change what is compiled: an SDK-style project whose default compile items are not disabled (in the project or a `Directory.Build.props`/`.targets` above it), no `<Compile>` item that matches only one of the old and new paths (an explicit `Include`, `Update` metadata, a `Remove` of the target folder), a file that declares nothing but the moved type and belongs to no other project, and a free target path. Those checks only read the project files, so after the move the project is re-evaluated with MSBuild (the same design-time load the workspace uses for incremental reconciliation), and unless MSBuild compiles the file at its new path in every target framework (an imported props file may remove the folder) the move is undone: the file goes back, folders the move created are removed, and the cached solution is restored. Whenever the file does not move, the namespace still changes and the result reports `PARTIAL_SUCCESS` with the reason (`preview` reports the project-file checks). The namespace change is written in place and the file is then moved, so it keeps its encoding; the cached solution is repointed at the new path (and folders) immediately, so the next tool call sees the file where it is on disk. The `using` the operation adds to referencing files now ends in the file's line ending instead of a hard-coded CRLF, and is followed by a blank line in a file that had no usings.
- `generate_tostring` honors `format`. The schema offered `"interpolated"` and `"stringbuilder"`, but every call generated an interpolated string. `"stringbuilder"` now builds the same text (`Person { Name = Ada, Age = 36 }`) with a `StringBuilder` local, named so that it never shadows an appended member and written as `StringBuilder` only where a `using System.Text;` allows it. Any other value is rejected with the new error `1017` (`InvalidParameterValue`) instead of being ignored. In the CLI, `--format` still selects the output format for `json`/`text` and is passed to the tool for any other value.
- Type names in generated code are no longer fully qualified when the file's usings make a shorter name available: `implement_interface` wrote `public event System.EventHandler Changed` and `int App.IRepository.this[int index]` next to `using System;` and inside `namespace App`. Generated type names (in `implement_interface`, `generate_overrides`, `extract_interface`, `encapsulate_field`, `generate_constructor`, `extract_variable` and `extract_constant`) are now marked for Roslyn's simplifier, which shortens just those names before the formatting pass. Nothing else in the file is simplified and no usings are added, so a name with no matching using stays qualified.
- `implement_interface` on a type that does not list the interface yet now adds it to the type's base list. Previously only the members were generated, so implicit stubs silently implemented nothing, explicit ones failed with CS0540, and members the type already had (that would implement the interface once it is listed) were generated a second time. The interface is now added first (after any existing base types) and the missing members are determined against the updated type. A name that resolves to a non-interface type, or to an open generic interface that would need type arguments, is rejected with `InterfaceNotFound` instead of being added.
- Generic methods generated by `implement_interface`, `generate_overrides` and `extract_interface` keep their type parameter constraints correctly. Stubs dropped every constraint, so implicitly implementing `T Clamp<T>(T value) where T : struct, IComparable<T>` produced a method that does not implement the interface member (CS0425), and an interface extracted from a constrained method no longer matched the class it came from (CS0425 once added to the base list). Interface methods and implicit implementations now restate all constraints (`class`/`class?`, `struct`, `unmanaged`, `notnull`, type constraints, `new()`, `allows ref struct`). Overrides and explicit implementations, which inherit their constraints, restate only what C# allows there: `class`/`struct`, and `default` for an unconstrained type parameter they write as `T?` (which would otherwise mean `Nullable<T>`).
- `generate_overrides`, `implement_interface`, `extract_interface` and `encapsulate_field` no longer write nullable annotations into code where they are disabled. Types were rendered with their symbol's annotations regardless of the target, so overriding `object.Equals(object?)` in a `<Nullable>disable</Nullable>` project produced `public override bool Equals(object? obj)` and `public override string? ToString()` — each a CS8632 warning — and the same happened for members of annotated interfaces. Reference types now get `?` only when nullable annotations are enabled where the code is inserted (honoring `#nullable` directives; a new file uses the project setting); in disabled code they are written without it.
- `add_missing_usings` on a file without any `using` directives now separates the new using block from the code after it with a blank line, instead of writing `using System.Collections.Generic;` directly above `namespace …`.
- Generated code uses the line ending of the file it is written into. Generated members were laid out by `NormalizeWhitespace()` (always CRLF), the formatter filled in line breaks with the platform's newline, and `add_missing_usings` ended new `using` lines with a hard-coded CRLF, so editing an LF file left it with mixed line endings — including the original line breaks next to an insertion (e.g. before the type's closing `}`) that the formatter re-laid out. The line ending is now taken from the document's existing text and applied to every line break in and around the generated code; an empty or new file (e.g. `extract_interface`/`extract_base_class` with a `targetFile`) uses the `.editorconfig` `end_of_line`, then the platform default.
- Refactorings no longer add a UTF-8 byte order mark to the files they edit. Every write went through `File.WriteAllTextAsync(..., Encoding.UTF8)`, which always emits `EF BB BF`, so any tool that touched a BOM-less file (the default for `dotnet new` and most editors) changed its encoding as a side effect, and UTF-16 files were silently converted to UTF-8. An existing file is now rewritten in the encoding its byte order mark indicates (UTF-8 without BOM when it has none); new files are still written as UTF-8 with BOM.
- Code generated by `generate_constructor`, `generate_overrides`, `generate_equals_hashcode`, `generate_tostring`, `implement_interface`, `add_null_checks`, `encapsulate_field`, `extract_interface`, `extract_base_class`, `extract_method`, `extract_constant` and `extract_variable` is now indented like the code around it. It was built with `NormalizeWhitespace()` (which lays a node out at column 0) and inserted with hard-coded line breaks, so new members, statements and types landed at column 0 with doubled blank lines, and `add_null_checks` glued its guard onto the method's opening brace; a base list added by `extract_interface`/`extract_base_class` came out as `class Person\n:IPerson{`. The inserted nodes are now marked and only they — plus the whitespace immediately around them — are run through the Roslyn formatter before the commit (honoring the project's `.editorconfig`); the rest of the file is never reformatted. `encapsulate_field` also no longer produces `privatestring Name;`: it prepended a bare `private` token, dropping both the replaced modifier's indentation and the space before the type, and now swaps the accessibility keyword in place.
- `generate_tostring` produces a `ToString()` that compiles. The interpolated string was assembled from text tokens whose source text held the literal braces unescaped, so every generated method read `$"Person { Name = {Name} }}"` and failed to compile. The braces are now escaped (`$"Person {{ Name = {Name}, Age = {Age} }}"`), and each run of literal text goes into a single token.
- `implement_interface`, `generate_overrides` and `extract_interface` now generate members that compile. **implement_interface** marked every stub `override` because interface members are abstract (CS0115), emitted each property/indexer/event accessor a second time as a standalone method (`get_Item`, `set_Name`, …), turned indexers into a property literally named `this[]`, and ignored members inherited from base interfaces (e.g. `Dispose` of an interface extending `IDisposable`). Interface members are now implemented as `public` members (or explicitly), accessors only through their property/indexer/event, indexers as real `this[...]` indexers, and members of base interfaces are included. **generate_overrides** always emitted `public` (CS0507 for a `protected` base member; a `protected internal` member from another assembly must be overridden as `protected`), dropped `ref`/`out`/`in`/`ref readonly` and `scoped` from parameters and from the `base.` call arguments, ignored `callBase` (default `true`) for properties so overrides became `return default;` plus an empty setter that silently discarded the base behaviour, emitted an indexer as a `this[]` property, emitted a member twice when an intermediate base class already overrode it (also `ToString`/`Equals`/`GetHashCode` once a base overrode them, CS0111), and offered `internal` members of other assemblies that cannot be overridden. Overrides now keep the base member's (and a restricted accessor's) accessibility, the parameter modifiers, call `base.Prop` / `base[i]` from property and indexer accessors, and each member is offered once. With `throwNotImplemented: false`, generated bodies also assign `out` parameters. **extract_interface** produced a property named `this[]` for indexers, dropped `ref`/`out`/`in` from method parameters, and copied a `private set` into the interface as a public setter the class cannot implement; it now emits real indexers, keeps parameter modifiers, includes only public accessors, and keeps `init` setters as `init`.
- `analyze_data_flow` and `analyze_control_flow` work on ordinary method bodies again. They took the first and last of *every* statement inside the line range, nested ones included, and handed those two to Roslyn — which requires siblings in one statement list. Whenever the range ended inside a nested block (a body ending in `if (x) { return y; }`) or covered a whole method (whose body block is itself a statement), the pair came from different lists, Roslyn threw, and the tool failed with error `4003`. The region is now the outermost statements fully inside the range; a whole method is analyzed through its body's statements, and a range that genuinely spans different blocks is rejected as `InvalidRegion` with a clear message. `analyze_data_flow` additionally accepts a range covering an expression-bodied member (`=> expr`) or a field/property/variable initializer, analyzing that single expression instead of reporting "No statements found".
- `extract_constant`, `extract_variable` and `extract_method` handle their selection input properly. `extract_constant` and `extract_variable` indexed the source lines without bounds checks, so a line past the end of the file (or a start after the end) surfaced as an internal `4003` error, and a column past the end of a line silently spilled into the next line; `extract_variable` also accepted an empty selection. All three now share `extract_method`'s bounds-checked position conversion and report `InvalidLineNumber` / `InvalidColumnNumber` / `InvalidSelectionRange`. `extract_variable` no longer drops the extracted expression's trivia, which fused the new name with a following keyword (`if (GetValue() is string s)` became `if (valueis string s)`; likewise `as`, `switch`, `with`). And `_` is refused as the new name for all three: a method, constant or local named `_` captures every existing discard in scope (`_ = Log(x)`, `out _`), breaking or silently changing that code.
- `sort_usings` (and `add_missing_usings`, which re-sorts the file's usings after adding) no longer moves a `global using` behind a normal `using`. The sorter ignored the `global` keyword and ordered every directive purely by group and name, so e.g. `global using App.Shared;` could end up after `using System;` — which does not compile (CS8915). Global usings are now sorted among themselves and always placed before all non-global ones.
- `add_missing_usings` and `remove_unused_usings` with `allFiles: true` now actually write their changes. Each per-file edit was pushed into the cached workspace mid-walk, and the final commit then compared that same snapshot against itself and found nothing to write: the result reported `usingDirectivesAdded`/`usingDirectivesRemoved` > 0 with an empty `filesModified`, disk was unchanged, and the cached solution kept edits that were never saved, so later tool calls worked on code that did not exist on disk. The edits are now accumulated locally and committed once, so the files are written and the cache matches disk.
- A source generator that resolves on disk but cannot actually be loaded is now reported as `RMCP0001` instead of silently contributing nothing. In the case that motivated it — an SDK's Razor generator built against a newer Roslyn than the server hosts — `GetGenerators` returns an empty array with no exception and no unresolved reference, so every `RZ` diagnostic (and every `CS` diagnostic from the generated `.g.cs`) disappeared while `get_diagnostics` reported a confident zero. Roslyn's `AnalyzerLoadFailed` event is now subscribed before compilations are materialized, and its `ReferencesNewerCompiler` code is translated into a message naming the host's Roslyn version and the fix. The Razor-generator matcher also knew only the pre-.NET 8 assembly name (`Razor.SourceGenerators`) and never recognised the .NET 8+ name `Microsoft.CodeAnalysis.Razor.Compiler`.
- Razor diagnostics work again on **SDK 10.0.400**: the host now references Roslyn 5.9.0 (was 5.6.0). The SDK's `Microsoft.CodeAnalysis.Razor.Compiler.dll` binds against `Microsoft.CodeAnalysis 5.9.0.0`, and assembly binding never rolls backward, so a 5.6.0 host loaded zero generators and every `RZ` diagnostic — along with the `CS` diagnostics from generator-emitted `.g.cs` — silently disappeared. The rule is that the host's Roslyn must be at least as new as the Roslyn shipped with the installed SDK; roll-forward keeps older SDKs working.
- Razor diagnostics work on **SDK 11.0.100**, whose Razor generator binds against `Microsoft.CodeAnalysis 5.12.0.0`; the host now references Roslyn 5.12.0 (same rule as above).
- Loading a standalone `.cs` file no longer deadlocks when the client talks to the server over synchronous pipes (e.g. Python's `subprocess`). The `git` and `dotnet restore` child processes inherited the server's stdin — the MCP protocol channel — and Git for Windows' MSYS runtime blocked at startup probing that pipe while the server had a read pending on it, so the call hung until the 5-minute load timeout. Child processes now always get their own (immediately closed) stdin. A per-step timeout is also no longer reported as cancellation of the whole load: a timed-out best-effort step is skipped, and a timed-out `run-api` falls back to the ad-hoc workspace.
- When MSBuildLocator finds no usable instance, the fallback SDK lookup compares parsed versions instead of folder names (ordinally `9.0.321` sorted above `11.0.100`) and skips SDKs newer than the host runtime, whose MSBuild it can't load.
- `rename_symbol` with `renameFile: true` no longer leaves the original file behind. The document was repointed at its new path *before* the commit, so the commit itself wrote the new file; the subsequent "does the target already exist?" check then found the operation's own output, skipped the move, and left the source file in place with the old type name. The collision check now runs before the commit, and the stale original is removed after it. A file that genuinely occupied the target path is no longer silently overwritten either — the rename is applied in place in the source file and reported as `PARTIAL_SUCCESS`, in `preview` mode too. A renamed file is now reported under `filesCreated`/`filesDeleted` rather than as a modification of a path that did not exist before the operation.
- `rename_symbol` now finds fields, events, and locals when a `line` is given without a `column`. It previously failed with "symbol not found" in that case, because the default column landed on the leading keyword (e.g. `private`) instead of the name. It now uses the same line-scanning resolution as `find_references` and `go_to_definition`.
- The server's own refactor writes (and genuine external edits shortly after) no longer trigger a full MSBuild reload. File-watcher `.cs` events are reconciled against settled disk + workspace state rather than blindly invalidating the cache.
- Cached workspace now reloads when a referenced generator assembly changes on disk, so stale source-generator output is no longer served after a `dotnet build`.
- Analyzer-reference rewrites (shadow-copy and unresolved-reference stripping) are kept in-memory and never persisted to the `.csproj` — previously every solution load rewrote project files with absolute `<Analyzer Include="…"/>` paths and mangled formatting (BOM, dropped blank lines/trailing newline).
- `get_diagnostics` no longer reports spurious Razor errors (RZ3600/RZ9985/RZ10009): the generator now receives the project's MSBuild properties (e.g. `RootNamespace`, `RazorLangVersion`) and leftover generator output is removed before re-running, so results match `dotnet build`.
- `get_diagnostics` with a `sourceFile` filter no longer silently returns an empty list when the path is equivalent but not byte-identical to the workspace's load-time-normalized document path — an 8.3 short-name component (e.g. `PROGRA~1` vs `Program Files`), mixed `/` vs `\` separators, or `..` segments. The caller's `sourceFile` is now normalized the same way as the diagnostic span paths before comparison.
- `extract_base_class` and `extract_interface` now normalize `targetFile` and `sourceFile` before deciding whether the target is a separate file, so passing the same file spelled differently (short-name component, mixed separators, `..` segments, or case) no longer incorrectly triggers the "create new file" branch. The new-vs-same-file decision is centralized in a `PathResolver.PathsEqual` helper now shared with `move_type_to_file`.
- Analyzers that MSBuild reports but the host can't load (missing DLL, target-framework mismatch) are dropped after load, fixing a `4003` error on the first tool call after an otherwise successful load.
- Cache-invalidation race (a concurrent reload could evict a freshly loaded entry), a leak that kept the old workspace and analyzer loader alive when the cache was invalidated while a tool call was still using it, and analyzer-loader locking/GC hardening.
- Responses now report timing broken out into the operation's own time (`executionTimeMs`), the workspace load time (`workspaceLoadMs`), and the combined total (`totalExecutionTimeMs`); previously the load time was lost on the way back.

  - `get_code_metrics` — calculate cyclomatic complexity, lines of code, maintainability index, class coupling, and depth of inheritance
  - `analyze_control_flow` — analyze control flow for a code region (reachability, return/exit points)
  - `analyze_data_flow` — analyze data flow for a code region (reads, writes, captured variables)
  - `get_document_outline` — get a hierarchical outline of all symbols in a file
  - `get_type_hierarchy` — retrieve base types and derived classes for a type

  **Code Generation & Formatting (4 tools)**
  - `generate_equals_hashcode` — generate Equals() and GetHashCode() overrides for a type
  - `generate_tostring` — generate ToString() override for a type
  - `format_document` — format a C# file using Roslyn's built-in formatter
  - `add_null_checks` — add null-check statements for method parameters

  **Code Conversions (7 tools)**
  - `convert_expression_body` — toggle between expression body and block body for methods/properties
  - `convert_property` — convert between auto-property and full property with backing field
  - `introduce_parameter` — promote a local variable to a method parameter, updating call sites
  - `convert_foreach_linq` — convert foreach loops with Add patterns to LINQ expressions
  - `convert_to_pattern_matching` — convert if/is chains and switch statements to switch expressions
  - `convert_to_interpolated_string` — convert string.Format() and concatenation to interpolated strings
  - `find_callers` — find all callers of a symbol across the solution

- `roslyn-cli` standalone CLI tool (`RoslynMcp.Cli` package)
  - All 41 Roslyn tools accessible from the command line without an AI assistant
  - JSON output by default (pipeable to `jq`), with `--format text` for human-readable output
  - Per-tool help via `roslyn-cli <tool-name> --help`
  - Exit codes: 0=success, 1=tool error, 2=CLI error, 3=environment error

- `QueryOperationBase<TParams, TResult>` — new base class for read-only query operations
- `SymbolResolver` — general-purpose symbol resolver (position-based and name-based)
- New contract models, error codes, and enums for all 22 new tools
